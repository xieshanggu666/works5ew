# 🏅 青春杯 · 体育赛事编排与成绩管理系统（SportFlow）

一个综合性运动会/联赛的赛事编排与成绩管理平台，支持多项目、多赛制（单循环 / 小组赛+淘汰赛 / 单败淘汰 / 田径计时）编排，参赛队伍与运动员注册、赛程自动排定、比分录入、积分排名、奖牌统计与成绩册输出。适用于校运会、省市级联赛等场景。

> 视觉风格：**明亮运动活力风**（浅色底 + 活力橙/绿茵/天际蓝），与工程内其他项目（深色科技风）刻意区分。

## 技术栈

- **前端**：Vue 3 + Vite + Pinia（状态管理）+ 原生 SVG/条形可视化
- **后端**：Express + Node.js 内置 `node:sqlite`（需 **Node ≥ 22**，低版本可用 `npx -y node@22 server/index.js` 启动后端）
- **数据库**：SQLite（`server/event.db`）
- **通信**：REST API，Vite 代理 `/api` 到后端
- **启动**：`concurrently` 并行拉起前后端（后端 4170 / 前端 5203）

## 数据模型（SQLite 表）

| 表 | 说明 |
|----|------|
| `sports` | 比赛项目（类别 / 赛制 format：roundrobin·group_knockout·knockout·track / 名额 quota） |
| `units` | 参赛单位（学院/俱乐部，含主题色） |
| `teams` | 队伍（归属单位 + 项目 + 状态 status：pending/approved/rejected/withdrawn/revoked） |
| `athletes` | 运动员（田径等单项 + 状态 status） |
| `venues` | 场地 |
| `referees` | 裁判（专长 sport / 等级 level：主裁·助理裁判·记录台） |
| `matches` | 对阵场次（小组/半决赛/决赛/季军，比分、决胜比分、胜方与状态 status：scheduled/finished/void，备注 note 记录弃权/成绩取消原因） |
| `assignments` | 裁判执法安排（场次×裁判×角色，status：assigned 在派 / released 已解除；场次-裁判在派唯一索引防重） |
| `assignment_logs` | 排班全量留痕（assign/force_assign/auto_assign/release/reassign/swap/match_change/schedule_added/schedule_rebuild/match_finish/void_release，含原因与操作人） |
| `entries` | 单项成绩（mark + rank） |
| `standings` | 积分榜（赛/胜/平/负/进失/积分/排名，仅统计已通过资格审核的队伍） |
| `medals` | 奖牌榜（金/银/铜） |
| `registrations` | 参赛报名与资格审核（kind：team/athlete，状态流转 pending→approved/rejected，退报 withdrawn / 撤销 revoked，含名额序号 quota_no、审核人与备注） |

## 核心算法

- **单循环**：两两配对生成 `n*(n-1)/2` 场，积分最高者为冠军。
- **小组赛 + 淘汰赛**：分组循环 → 按每组积分排名（胜 3 / 平 1 / 负 0，净胜球次序）→ `A1 vs B2`、`B1 vs A2` 交叉半决赛 → 决赛 + 季军战。
- **单败淘汰**：半决赛 → 胜者晋级决赛、负者争季军。
- **淘汰赛平分决胜**：半决赛/决赛/季军战常规时间战平时，必须录入加时/点球决胜比分（不得再次持平），系统以决胜结果确定胜方并持久化到 `matches.winner`；晋级编排、奖牌结算、对阵展示统一读取该字段，未决胜前不会生成下一轮对阵。决胜比分不计入进失球。
- **田径计时**：成绩升序自动排名，前 3 结算金/银/铜。
- **奖牌统计**：按单位累计各项目冠军/亚军/季军。

淘汰赛对阵不是一次性预排，而是**按当前小组赛/半决赛真实赛果动态生成**——在"赛程编排"页当小组赛（或半决赛）完赛后点击"🧩 编排下一轮淘汰赛"，系统读取实时排名后自动填入对阵。

## 核心流程

**参赛资格审核**（报名审核页）：各单位提交队伍/运动员报名 → 组委会审核资格与名额（通过数不得超过项目名额上限）→ 通过后纳入参赛名单；循环赛项目若尚未开赛则自动重排对阵，把新队伍纳入赛程。退报或资格撤销时**同步处理受影响的对阵及成绩**：未赛场次判弃权（对手 3:0 胜），已赛场次取消成绩并重算积分榜与奖牌；田径项目删除该运动员成绩并重排名。

**赛事编排**：赛程编排（自动生成对阵）→ 录入比分（成绩录入页）→ 积分榜/排名自动更新 → 完赛阶段动态编排下一轮淘汰赛 → 单项目决出冠亚季 → 汇总至奖牌榜与报表中心。

## 裁判排班与场地协同

在「📍 场地裁判」页提供四个协同视图：

1. **排班总览**：按项目列出全部待赛场次的执法名单（主裁/助理/记录台），可逐场安排、🤖 一键智能排班（专长匹配优先 → 待赛负荷均衡 → 无时间冲突）。顶部统计卡与预警条实时汇总待安排、撞档、跨专长。
2. **场地协同**：各场地时段排布与同时段撞场预警，可就地跳转处理。
3. **裁判名册**：专长/等级/状态 + 已执法/待执法负荷、冲突标记，支持录入新裁判。
4. **变更留痕**：排班、强制覆盖、临时调班（改派/对调，必填原因）、解除、赛程变更、赛程新增/重排、完赛归档、退报取消解除——全部写入 `assignment_logs`，带原因与操作人可追溯。

**冲突检测规则**：同一裁判同一 `time_label` 不得执法两场待赛（任意角色都算占用）；同场地同时段不得排两场。排班时还校验裁判专长（专长不符默认拦截，可在填写原因后**强制安排**并标记预警）。临时调班（改派/对调）同样做专长与冲突预检。

**赛程变更联动执法安排**：调整场次时间/场地时，先应用变更再基于"变更后"全局状态检测，有冲突默认回滚，可强制生效并留痕；新生成的淘汰赛/半决赛场次自动安排主裁；报名通过触发循环赛重排时，旧场次执法安排全部解除并留痕；退报/撤销资格导致的弃权（判 3:0 完赛 → 执法记录归档）与成绩取消（场次 void → 解除在派裁判）均联动；比分录入页与赛程页显示主裁，未派主裁录入比分时返回预警；总览页与报表中心展示待派主裁数、覆盖率、执法工作量与最新变更。
